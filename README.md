# vape-parser

Парсер публичных Telegram-каналов вейп-шопов через личный аккаунт (Telethon).
Собирает название, ссылку, число подписчиков, контакт админа, признак
"есть ли уже бот-каталог" и дату последнего поста. Результаты сохраняются
в SQLite и экспортируются в Excel.

## Структура проекта

- `config.py` — конфигурация, читает секреты из `.env`
- `db.py` — работа с SQLite (таблица `shops`, дедупликация по username)
- `heuristics.py` — регэкспы/правила поиска контакта админа и определения бота
- `parser.py` — вся логика Telethon: получение данных канала, поиск по ключевым словам, обработка `FloodWaitError`
- `exporter.py` — экспорт из SQLite в `.xlsx`
- `main.py` — CLI-точка входа, прогресс-бар, итоговая сводка
- `channels.txt` — список каналов по умолчанию

## Установка

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Получение api_id и api_hash

1. Зайдите на https://my.telegram.org под своим номером телефона.
2. Откройте **API development tools**.
3. Заполните форму (название приложения можно указать любое, например "vape-parser").
4. Скопируйте выданные `api_id` и `api_hash`.

## Настройка

```bash
cp .env.example .env
```

Заполните в `.env`:

```
TG_API_ID=123456
TG_API_HASH=ваш_api_hash
TG_PHONE=+79991234567
```

## Список каналов

Впишите каналы в `channels.txt` (по одному на строку, `username`,
`@username` или `https://t.me/username`) — либо передайте их через
`--channels` или отдельный файл через `--channels-file`.

## Первый запуск и авторизация

```bash
python main.py --channels-file channels.txt
```

При первом запуске Telethon попросит:
1. Код подтверждения, присланный в Telegram на ваш аккаунт.
2. Пароль облачного пароля (2FA), если он у вас включён.

После успешной авторизации создастся файл сессии
(`vape_parser_session.session`) — повторные запуски проходят без
повторного ввода кода, пока сессия не будет удалена/протухнет.

## Использование

```bash
# Парсинг списка из channels.txt (по умолчанию)
python main.py

# Явный список каналов через запятую
python main.py --channels vapeshop1,vapeshop2,vapeshop3

# Свой файл со списком каналов
python main.py --channels-file my_channels.txt

# Включить поиск новых каналов по ключевым словам (Telegram Global Search)
python main.py --enable-search
python main.py --enable-search --search-keywords "vape shop,жидкости для вейпа"

# Только пересобрать Excel-отчёт из уже накопленной БД, без парсинга
python main.py --export-only
```

По завершении:
- Данные лежат в `vape_shops.db` (таблица `shops`).
- Отчёт экспортируется в `vape_shops.xlsx`.
- Ошибки (приватные каналы, не найдено, и т.п.) пишутся в `parser_errors.log`, не прерывая прогон.
- В консоли выводится прогресс-бар и сводка: сколько каналов обработано и сколько из них "без бота" (целевые лиды).

## Как определяется контакт админа

По приоритету:
1. Описание канала (`about`).
2. Закреплённое сообщение.
3. Последние `MESSAGES_TO_SCAN` сообщений (по умолчанию 20).
4. Если ничего не найдено и явных признаков бота нет — участники привязанного
   чата обсуждений (только если список участников открыт для вашего аккаунта;
   часто это не так, и тогда основным источником остаются описание/посты).

Если канал уже похож на канал с рабочим ботом-каталогом (по ключевым словам
вроде "бот", "каталог", "меню", наличию inline-кнопок в сообщениях или
username, заканчивающемуся на `bot`), парсер помечает его `возможно есть бот`
и **не тратит запрос** на дорогой по rate-limit поиск админов через список
участников — такие каналы всё равно попадают в таблицу, просто с этой пометкой.

## Rate limiting

- Между обработкой каналов и запросами поиска выдерживается пауза
  `REQUEST_DELAY_SECONDS` (по умолчанию 2 сек, настраивается в `.env`).
- При `FloodWaitError` парсер автоматически засыпает на нужное время
  (`e.seconds`) и повторяет запрос — прогон не падает.
- Ошибки по отдельным каналам (приватный канал, канал не найден и т.п.)
  логируются в `parser_errors.log` и не прерывают весь прогон.

## Повторные запуски

Дедупликация происходит по `username` канала: при повторном запуске
существующая запись в БД обновляется свежими данными, а не дублируется.

## Важно

- Работа идёт через ваш личный аккаунт, а не через Bot API — это единственный
  способ читать описания/участников произвольных публичных каналов без
  собственного бота в них. Слишком частые/массовые запросы подряд могут
  привести к временным ограничениям (`FloodWaitError`) или, в крайнем случае,
  к блокировке аккаунта — не снижайте `REQUEST_DELAY_SECONDS` без необходимости
  и не парсите тысячи каналов за один прогон.
- `get_participants` для поиска админов сработает только там, где список
  участников открыт — это не гарантировано на большинстве публичных каналов.
- Собранные контактные данные — работайте с ними ответственно и в соответствии
  с применимым законодательством о защите персональных данных и правилами
  использования Telegram.
