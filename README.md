# HstlGram

Telegram Mini App — соцсеть для young businessmen. Дизайн ленты вдохновлён Threads,
механика знакомств — свайп-карточки в духе Дайвинчика (лайк/пропуск → мэтч → чат).
«Вакансии» — полноценная публикация офферов с модерацией доступа админом.
Заглушек нет — все вкладки полностью рабочие.

## Структура

```
backend/    Node.js + Express + PostgreSQL (Prisma) + Telegram-бот (grammy)
frontend/   React + Vite + TypeScript, Telegram WebApp SDK
```

### Вкладки Mini App

- **Лента** — посты, лайки, комментарии.
- **Знакомства** — свайп анкет (лайк/пропуск), при взаимном лайке — мэтч и чат.
  Анкета попадает в свайп **только после одобрения админом**.
- **Вакансии** — публикация офферов доступна только пользователям, которым
  **админ выдал разрешение** (запрашивается кнопкой в этой же вкладке).
- **Профиль** — данные пользователя, статус модерации анкеты знакомств,
  кнопка «Связь с администратором» (открывает [@saintsoon](https://t.me/saintsoon)).
- **Админ** *(видна только админам)* — модерация анкет знакомств (одобрить/
  отклонить/удалить), заявки на публикацию офферов, список всех офферов с
  удалением, управление пользователями (право на офферы, назначение/снятие
  админки, удаление анкеты у любого пользователя) и рассылка сообщения всем
  пользователям бота.

### Роли и права

- **Админ** назначается через переменную окружения `ADMIN_TELEGRAM_IDS` (numeric
  Telegram ID через запятую) — при каждом входе такой пользователь получает
  `isAdmin=true`. Дальше админ может назначать/снимать админку другим прямо
  из панели («Пользователи» → «Сделать админом»).
- **Право публиковать офферы** (`canPostOffers`) выдаётся только админом —
  либо через заявку пользователя («Запросить доступ» в «Вакансиях» →
  админ одобряет/отклоняет), либо напрямую в «Пользователи».
- **Анкета знакомств** при включении/редактировании уходит в статус
  `PENDING` и не показывается в свайпе, пока админ её не одобрит
  («Анкеты» в админке). При отклонении «Знакомства» автоматически
  выключаются, пользователь видит причину в профиле.
- Кнопка «Связь с администратором» есть в профиле и в «Вакансиях» (при
  отсутствии/отклонении доступа) — открывает диалог с
  [@saintsoon](https://t.me/saintsoon) в Telegram.

### Бот: антибот-капча и уведомления админам

- При `/start` бот присылает простую математическую капчу (4 варианта
  ответа кнопками) — кнопка «Открыть HstlGram» показывается только после
  верного ответа. Повторно капча не запрашивается: успешное прохождение
  запоминается в БД (`captchaVerified`).
- Проверка не косметическая: backend отклоняет (`403 captcha_required`)
  любой запрос к API от пользователя без `captchaVerified=true` — то есть
  капчу нельзя обойти, например, открыв Mini App напрямую через постоянную
  кнопку меню бота, минуя `/start`. Фронтенд в этом случае показывает
  экран «Подтвердите, что вы не бот» с кнопкой открытия чата с ботом
  (нужен `VITE_BOT_USERNAME` во фронтенд-`.env`, см. ниже).
- При первом успешном прохождении капчи (то есть при регистрации нового
  пользователя) всем админам из `ADMIN_TELEGRAM_IDS` бот присылает личное
  сообщение с именем/юзернеймом нового пользователя.
- Рассылка всем пользователям бота — в админ-панели, вкладка «Рассылка».
  Отправка идёт с небольшой задержкой между сообщениями (лимиты Telegram),
  результат показывает, скольким доставлено.

## Как это работает

1. Пользователь открывает бота в Telegram, нажимает кнопку меню/`/start` → открывается Mini App.
2. Frontend получает `Telegram.WebApp.initData` и отправляет его в заголовке
   `X-Telegram-Init-Data` с каждым запросом к API.
3. Backend проверяет подпись `initData` секретом бота (`BOT_TOKEN`) и создаёт/находит
   пользователя в БД — отдельная авторизация (логин/пароль) не нужна.

## Запуск локально

### 1. PostgreSQL

Поднимите локальный Postgres (Docker пример):

```bash
docker run --name hstlgram-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=hstlgram -p 5432:5432 -d postgres:16
```

### 2. Backend

```bash
cd backend
cp .env.example .env   # заполните BOT_TOKEN, DATABASE_URL, WEBAPP_URL
npm install
npm run prisma:migrate # создаст таблицы
npm run dev            # http://localhost:3000
```

`BOT_TOKEN` берётся у [@BotFather](https://t.me/BotFather) (`/newbot`).
Пока Mini App не задеплоен, `WEBAPP_URL` можно оставить пустым — бот запустится,
просто кнопка запуска приложения в Telegram работать не будет.

Чтобы получить доступ к админ-панели, впишите свой numeric Telegram ID в
`ADMIN_TELEGRAM_IDS` (узнать его можно у [@userinfobot](https://t.me/userinfobot))
и перезайдите в Mini App — появится вкладка «Админ».

### 3. Frontend

```bash
cd frontend
cp .env.example .env   # VITE_API_URL=http://localhost:3000/api, VITE_BOT_USERNAME=имя_бота
npm install
npm run dev             # http://localhost:5173
```

`VITE_BOT_USERNAME` (без `@`) нужен для кнопки «Открыть бота» на экране
антибот-проверки — без него та кнопка просто ничего не сделает.

### 4. Разработка вне Telegram

Внутри Telegram `window.Telegram.WebApp.initData` доступен автоматически.
Для локальной разработки в обычном браузере (без Telegram) backend поддерживает
dev-обход: заполните `VITE_DEV_USER_ID` в `frontend/.env` любым значением
(например `123`) — фронтенд начнёт слать заголовок `X-Dev-User`, и backend создаст
тестового пользователя. Работает только при `NODE_ENV !== "production"`.

## Деплой

1. **Backend**: любой Node-хостинг (Railway, Render, VPS + PM2/Docker) + managed PostgreSQL.
   Задайте `BOT_TOKEN`, `DATABASE_URL`, `WEBAPP_URL` (адрес задеплоенного фронтенда),
   `CORS_ORIGIN`. Примените миграции (`npm run prisma:migrate`) и `npm run build && npm start`.
2. **Frontend**: статический хостинг (Vercel/Netlify/Cloudflare Pages), обязательно **HTTPS**
   (требование Telegram Mini Apps). Задайте `VITE_API_URL` = адрес backend `/api`.
3. В [@BotFather](https://t.me/BotFather): `/mybots` → бот → **Bot Settings → Menu Button**
   → укажите URL задеплоенного фронтенда (или это делает сам бот через `setChatMenuButton`
   при старте, если `WEBAPP_URL` задан).

## Что дальше (не входит в MVP)

- Загрузка фото (сейчас — по прямой ссылке URL) — нужен объектный storage (S3/Cloudflare R2).
- Realtime-чат через WebSocket/Socket.io вместо поллинга каждые 3с.
- Модерация контента ленты (посты/комментарии) — сейчас модерируются только
  анкеты знакомств и офферы/право на их публикацию.
- Пагинация и уведомления в админ-панели (сейчас список пользователей ограничен 100).
